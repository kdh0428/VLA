## 4. 추가 과제와 대안 모델 조사

### C. SpatialVLA 추가 과제 — 최대 1개, 보조 분석

두 task의 주 분석 panel과 estimand는 아래 명세대로 유지한다. 추가 과제 결과를 주 분석에 사후 혼합하지 않는다.

- 기존 SimplerEnv에서 **open-drawer → close-drawer 순서**로 환경 ID·robot embodiment·관측·normalization·checkpoint 호환성을 CPU 코드로 확인한다. 정확한 ID는 로컬 registry에서 확인한다.
- 첫 번째 호환 가능한 과제 하나를 선택한다. 선택 근거는 환경·개입 호환성이며 모델의 성공률이나 Delta가 아니다.
- 호환 과제가 없거나 새 학습이 필요하면 그 사실을 결과로 제출하고 E/F로 계속 진행한다.
- 최대 20개의 서로 다른 물리 layout/reset state, generation call 2/6/10, 최대 60관측으로 제한한다.
- seed 후보 5000–5099를 순서대로 조사하고 최초 20개 고유 layout을 고정한다. 사용 가능한 고유 layout이 적으면 그대로 보고한다.
- B와 동일한 source 거리 조건·최대 64회 sampling·N/R/L/O/OL·정규화 거리 정의를 사용한다.
- 새 intervention 결과를 보기 전에 표본·선택 규칙·분모·분석을 고정한다.
- 과제 내 layout 평균·layout-bootstrap 구간을 별도로 보고한다. 세 과제를 task 모집단 표본처럼 취급하지 않는다.
- 관측이 적거나 매칭 source가 부족해도 그 결과를 숨기거나 다른 과제의 유리한 결과로 교체하지 않는다.

### D. 대안 모델 — 실험 질문과의 적합성을 명시

공식 논문·코드·체크포인트만 근거로 다음을 한 표에 정리하라.
- 기반 모델 계열, 행동 표현, 시간별 행동과 token 위치의 대응.
- native autoregressive prefix 개입 가능 여부.
- 기존 평가 환경과 checkpoint의 embodiment·입력 호환성.
- 같은 위치 비교를 할 수 있는지, 다른 연구 질문이나 구조적 대조군에 해당하는지.
- 로컬 확인 / 공개 자료 확인 / 미확인 항목 구분.
- 추가 설치·가중치·학습이 필요한 부분과 선택 또는 보류 이유.

π0-FAST의 압축 token 위치를 물리 행동의 이전/최근 시점으로 바로 해석하지 않는다. WorldVLA의 action attention mask와 원본 OpenVLA/OFT의 decoding 방식을 실제 소스에서 구분한다. 조사·코드 확인만 한 정책을 신규 실험 모델 수에 포함하지 않는다.

## 5. 기여·일반화 분석과 원고 v03

실험 결과를 확보하면 별도의 논문 수정 허가를 기다리지 말고, 기준 v02의 실제 TeX를 바탕으로 **검토 가능한 v03 소스와 PDF**를 만들어라. 실험이 부분 완료되어도 그 범위에 맞는 원고를 완성한다.

반드시 정리할 것:
- AutoVLA, VLA-0, SpatialVLA에 대해 **개입 위치·고정된 prefix·donor·응답 구간·실제 실행 여부·결과 지표·독립 단위**를 나란히 비교한다.
- AutoVLA의 latest-position contrast와 VLA-0의 직접 L/O 비교를 동일한 검정처럼 묶지 않는다.
- SpatialVLA의 v01 discovery, 새 거리 매칭 후속, 추가 과제 결과를 분리한다. source 선택 규칙을 바꾼 후속임을 명시한다.
- 출력 명령 변화, 실행 운동 반응, 과제 성공을 각 증거의 실제 개입과 연결한다. 서로 다른 개입에서 얻은 결과를 하나의 동일한 인과 경로처럼 합치지 않는다.
- 이전 위치 편집 후 중간 행동을 자연값으로 강제한다는 조건을 설명한다. 이는 전체 오류 전파와 다르다.
- “다른 백본·표현에서도 관측됐다”와 “백본의 인과 효과를 분리했다”를 구분한다.
- task 유형 수, 물리 layout 수, 초기 상태·시간별 관측 수를 별도로 제시한다.
- 기여가 기존 선행 연구에 더하는 구체적인 발견을 데이터에 맞춰 적는다. 결과가 작으면 적용 범위·모델 의존성으로 정리한다.

원고 반영 규칙:
- 매칭 후속의 coverage와 구간이 뒷받침하면 제한된 task/checkpoint 범위의 교차 백본 근거로 반영한다.
- 정보가 부족하면 경로 검증·탐색적 결과로 표시한다. v01의 보조 분석 0.070을 주 분석으로 승격시키지 않는다.
- 새 성능 개선법이나 성공률 향상이 생긴 것처럼 쓰지 않는다.
- 기존 VLA-0 수식 정정 D(OL,L), motion 구간, SpatialVLA task별 8개 효과, 표준 PDMS 근거와 상위 군집 한계를 보존한다.
- 본문은 **8쪽**으로 유지한다. 작은 글씨나 style 수정으로 억지로 맞추지 않는다.
- 핵심 결과는 본문에서 읽을 수 있는 작은 표 또는 그림으로 제시하고, 세부 분모·프로토콜·추가 그림은 전체 보충자료에 통합한다. 기존 A–O를 누락시키지 않는다.
- 모델 선택 근거는 과학적 질문과 개입 적합성으로 설명하고, 기존 환경 재사용은 구현상 이유로 분리한다.
- 공개 출처는 서지 metadata와 실제 인용을 확인한다. 특정 리뷰어의 불완전한 인용을 임의로 식별하지 않는다.

| GPU 시간 | 기록된 ledger 합계 20.0918 model-GPU minutes |

독립 확인에서는 공식 공개 action tokenizer의 복호화 규칙과 processor config의 bin 값으로 NumPy decoder를 별도 구현했다. 자연 행동, 모든 기록된 arm 행동, source 거리와 donor 선택, layout→task 집계 및 bootstrap 구간이 원시 기록과 일치했다. 4,767개 assertion은 검증 항목 수이며 표본 수가 아니다.

**범위:** 로컬에서 모델 추론·물리 시뮬레이션을 다시 실행하지 않았다. logit 차이가 0이라는 항목은 서버 실행 로그의 값이고, token equality와 통계는 저장된 원시 자료로 확인했다. 공개 processor config의 bin 값은 모든 기록된 decoded action과 source 거리를 재현했지만, 실행 당시 config 자체가 ZIP에 없으므로 해당 config 파일의 byte identity까지 인증한 것은 아니다.

## R3. 원고에서 바로 고쳐야 할 해석

### R3.1 보조 분석을 주 분석처럼 쓰지 않기

제출된 CLAIM_DELTA는 초록에서 0.070 [0.044, 0.100]을 앞세우고, 소제목에 “latest action dominates in a second backbone family”를 제안한다. 현재는 이 문구를 채택하지 않는다.

- 0.070은 사전 정의한 **보조 분석**이다.
- L donor의 평균 거리가 더 크다. 평균 거리 차이가 효과 전체를 설명한다고 단정할 수도 없지만, 현재 자료로 거리 교란을 배제할 수도 없다.
- 사전 정의한 매칭 분석은 move_near가 1 layout이라 두-task 추론 구간이 NA다.
- E/d 비율 또는 거리와 반응의 상관만으로 이 문제를 해결했다고 해석하지 않는다.

현재 쓸 수 있는 범위는 **다른 기반 모델 계열에서 within-call 경로를 검증했고, 해당 donor 규칙 아래 두 과제에서 같은 방향의 탐색적 위치 반응을 관찰했다**는 것이다.

### R3.2 이전 위치의 ‘전체 영향’을 측정한 것은 아님

O arm은 a1을 바꾸면서 a2를 자연값으로 강제한다. 따라서 a1 변경이 a2를 바꾸고 다시 a3–a4로 전파되는 경로는 고정되어 있다. 이 실험은 **고정된 중간 행동 아래의 위치별 문맥 반응**이다.

이 조건을 본문에 짧게 명시하고, 일반적인 시간적 의존성·완전한 오류 전파·무조건적인 latest 지배로 확장하지 않는다. VLA-0와의 비교에서도 같은 개입 의미를 유지한다.

### R3.3 fresh-cache 평가 경로를 명시하기

A3 수정 후 N과 intervention 모두 호출별 fresh cache를 사용한다. 이를 **공식 모델·processor를 사용하면서 호출마다 cache를 초기화한 평가 경로**라고 쓰는 것이 정확하다.

- 첫 pilot의 4/105 R 실패와 7/105 official 출력 차이, 진단, 재실행은 보존한다.
- cache 재사용과 출력 차이의 연관 및 초기화 후 parity 회복은 기록되어 있다.
- BF16 수치 연산이 모든 차이의 원인이라고 확정하지 않는다. 최초 시도의 남은 불일치 3개는 완전히 분리되지 않았다.
- 자연 adapter의 일부 logit 최대 차이 0.125와 R continuation logit 차이 0.0을 구분한다.
- 이 구현 이슈를 새로운 성능 개선법으로 주장하지 않는다.

### R3.4 기존 성공률 연구와 구분하기

새 within-call 실험은 명령 수준의 결과다. 기존 cross-step 성공률의 두-task 평균 ±10 pp를 이 개입의 성공률 동등성으로 옮겨 쓰지 않는다. 주행의 상위 군집 한계도 그대로다.

## R4. 추가 CPU 조사: 기존 source만 재선택하면 충분한가?

기존 420개 source 후보에서 ‘첫 joint-valid’ 제한을 풀고 **어떤 후보라도 거리 매칭을 만족하는지**만 조사했다. 새 continuation을 생성하거나 결과를 바꾸지는 않았다.

| 기존 pool의 매칭 가능성 | coke | move_near | 합계 |
| --- | ---: | ---: | ---: |
| 매칭 후보가 하나 이상 있는 관측 | 14 | 2 | 16 |
| 해당 물리 layout 수 | 13 | 2 | 15 |

따라서 기존 pool에서 donor를 바꾸는 것만으로 move_near의 표본 부족을 충분히 해결하기 어렵다. 미선택 donor의 continuation 효과는 현재 알 수 없다. 이 16개를 새 효과 표본처럼 보고하지 않는다.

현재 선택된 매칭 관측 7개에서는 두 위치의 변경 token 종류(translation/rotation)의 패턴도 모두 같다. 더 큰 pool을 쓰는 후속에서는 이 패턴을 함께 기록하고 보조 분석으로 점검한다.

# E. B 작업의 구체적인 거리 매칭 실행 명세

아래 사전 고정·표본·donor·분석 정의를 따른다. 예산은 위 통합 지시의 B 60분/C 30분/전체 150분 규칙을 적용한다.

## E6. 먼저 재현 자료를 보완

GPU를 쓰기 전에 v01 실행 환경의 다음 자료를 작은 snapshot으로 보존하라.
- 실제 processor_config.json, action_tokenizer.py, generation_config.json 및 token type ID 범위.
- 모델·processor·cache 관련 실제 사용 source와 revision, 파일 해시.
- 관측 수집에 사용한 PolicyState와 worker/전처리 source 또는 고정된 저장소 revision.
- v01 분석의 standalone CPU verifier. 실행 서버의 절대 경로나 AutoProcessor 초기화에 의존하지 않고, 패키지에 포함된 config/bin 값으로 raw token을 복호화할 수 있게 한다.

실행 당시 fingerprint와 snapshot 해시가 맞는지 확인하라. 현재 source가 바뀌었다면 byte identity를 억지로 주장하지 말고 버전 차이를 기록한다. 모델 weight는 ZIP에 복제할 필요 없이 기존 revision과 weight 해시를 제공한다.

v01 수치와 분모를 재계산한다. 여기서 primary 7관측 / CI NA와 secondary 64관측을 그대로 유지한다.

## E7. 새 표본과 계획을 먼저 고정

새 intervention suffix 결과를 만들기 전에 `PROTOCOL_20261023_v02.md`, 표본 manifest, donor 선택 규칙, 분석 코드의 SHA 또는 commit을 고정하라.

표본은 두 task를 유지한다.
- coke: seeds 4000–4099를 순서대로 CPU survey하고, 기존 v01 및 validation과 겹치지 않는 최초 25개 layout을 선택한다. 기존 coarse layout fingerprint와 함께 full object pose도 저장한다. 후보 안에서 25개를 확보하지 못하면 실제 확보 수를 고정하고 보고한다.
- move_near: v01의 10개 layout과 동일한 대표 seed·instruction을 사용한다. 재사용 layout이라는 사실을 유지한다.
- 자연 policy generation call **2,6,10**의 관측을 수집한다. 환경 step과 generation call 대응을 기록한다.
- 최대 105관측이다. episode가 먼저 끝나면 이후 관측을 복제하지 않는다.
- input image hash, layout fingerprint, instruction을 기록해 v01과 정확히 같은 입력이 있는지도 공개한다. move_near의 재사용 layout을 새 독립 layout으로 세지 않는다.

v01은 발견 단계, v02는 새 donor 규칙을 미리 고정한 후속이다. 과제·layout의 재사용 때문에 전체가 독립적인 task-generalization 검증이라고 부르지 않는다. v01·v02 관측을 단순 합쳐 표본 수를 부풀리지 않는다.

## E8. 새 donor 규칙: 거리 조건을 먼저 만족시키기

N/R/L/O/OL, 행동 번호, emitted prefix 고정, 정규화 6D 거리와 gripper 고정은 v01과 같다. fresh-cache 수정도 유지한다.

관측마다:
1. 공식 sampling 경로에서 T=0.7, top_p=1.0, top_k=0으로 **최대 64개**의 source chunk를 순서대로 생성한다.
2. seed는 `sha256("svla_wc_v02_src:" + obs_id + ":" + j)`의 앞 4바이트를 little-endian 정수로 바꿔 사용한다. j는 0부터 시작한다.
3. a1,a2의 token type이 유효하고, 두 gripper가 자연값과 같고, d_O,d_L > 0인 후보만 joint-valid다.
4. 그중 **0.8 <= d_L/d_O <= 1.25를 처음 만족하는 후보 하나**를 O/L/OL에 공통 사용한다.
5. 첫 matched 후보를 찾으면 source sampling을 멈춰도 된다. 아직 L/O/OL continuation은 생성하지 않은 상태에서 선택을 확정한다.
6. 64개 안에 없으면 MATCHED_SOURCE_MISSING으로 기록한다. 추가 seed·temperature 탐색, 거리 허용폭 확대, 결과를 본 재선택은 하지 않는다.
7. 실제 생성한 후보 전체와 거절 이유·거리·선택 index를 보존한다. source에서 a3,a4가 생성되더라도 donor 선택은 a1,a2와 거리 조건에만 의존한다.

두 위치의 translation/rotation 변경 여부도 기록한다. 같은 변경 유형 패턴의 subset은 사전에 정의한 보조 분석으로 보고하되, 원하는 부호를 얻기 위해 주 분석 표본을 바꾸지 않는다.

## E9. 경로와 실행 중 검사

v01 final에서 통과한 fresh-cache 경로를 사용한다. 동일 경로를 다시 구현하거나 precision/kernel을 바꾸지 않는다.

- 시작 시 coke와 move_near를 모두 포함한 소수의 smoke 관측으로 native/adapter/R 일치를 확인한다.
- 본 실행의 모든 관측에서 N/R 원시 token과 EOS, 복호화 행동, 수집 시 natural 출력 일치를 확인한다.
- 짧은 출력·잘못된 token type을 parser padding/clipping으로 유효하게 만들지 않는다.
- R 불일치 시 해당 실행의 효과 해석을 멈추고 원시 기록을 남긴다. 불일치 관측만 버려 긍정적인 표를 만들지 않는다.
- checkpoint/seed/표본/metric을 효과 방향에 따라 바꾸지 않는다.

## E10. 주 분석과 해석

v01과 같은 식을 사용한다.
- D(X,Y): a3,a4의 정규화 6개 운동 성분에 대한 평균 절대 차이, 분모 12.
- E_L=D(L,R), E_O=D(O,R), Delta=E_L−E_O.
- layout 내 관측 평균 → task 내 layout 동일 가중치 → 두 task 동일 가중치.
- task를 고정한 층으로 두고 layout 전체를 resample하는 bootstrap 10,000회, seed 20261023, 95% percentile interval.
- 한 task의 유효 layout이 1개 이하이면 두-task 구간은 NA다. 한 task의 매칭 관측이 없으면 두-task 점추정도 NA다.
- D(OL,L)은 직접 벡터 거리를 계산한다. J=E_OL−E_O−E_L은 보조 기술량이고 동등성 검정이 아니다.

분모:
후보 layout → 수집 관측 → 유효 자연 출력 → R 통과 → matched source 확보 → 유효 arm → 최종 분석.
과제별·layout별·관측별 수, source 시도 수와 거절 이유, 거리 비율 분포를 공개한다.

**계획상 coverage 목표:** coke 15개 이상, move_near 8개 이상의 유효 matched layout이다. 이는 충분한 검정력을 계산한 기준이 아니며, 소수 layout에만 의존하는 결과를 피하기 위한 설계 목표다. 고정 표본·64-source 상한에서 나온 실제 coverage를 보고한다. 목표 미달을 이유로 무제한 source나 관측을 추가하지 않는다.

보조 분석:
- task별, a3/a4별, translation/rotation별 반응.
- 두 위치의 변경 token 종류 패턴이 같은 subset.
- gripper 변화율과 D(OL,L).
- 관측·layout별 Delta 분포 및 donor 거리.
- v01 결과와 나란히 제시하되, donor 선택 규칙·관측이 달라진 별도 실험임을 표기.

L>O뿐 아니라 작은 효과·반대 효과도 그대로 제출한다. 유의성이나 CI 부호를 완료 조건으로 삼지 않는다. 정규화 command 차이를 실제 이동 거리로 표현하지 않는다.



이 명세의 standalone verifier 보완과 실험이 끝나면, 위 E/F 작업으로 이어서 원고 v03 및 최종 패키지까지 완료한다.
