## 실행 여부와 결론
- **실행:** feasibility와 pilot을 모두 실제로 수행했습니다. GPU 사용은 **20.1 model-GPU분**(상한 150분)이며, 실패 시도·진단·재실행을 모두 포함합니다. RTX 5090 1장만 썼습니다.
- **경로 검증:** **PASS**입니다.
  - validation 12개에서 self-patch 원시 token 동일 12/12, 복호화 행동·종료 token·logit도 bitwise 동일했습니다.
  - pilot 105개에서도 R 동일 105/105였습니다.
  - 공식 `generate`와 adapter 자연 출력은 105/105 일치했습니다.
- **주 분석:** 사전 고정한 거리 매칭 분석은 표본이 부족합니다.
  - 매칭을 만족한 관측이 7개(coke 6, move_near 1 layout)뿐이라 두 task의 구간은 NA입니다(점추정 Δ=0.084).
- **보조 분석(joint-valid 전체):** 64관측·32 layout에서 Δ=E_L−E_O=**0.070 [0.044, 0.100]**입니다.
  - 두 task 모두, a3와 a4 모두, translation과 rotation 모두에서 최근 행동(a2)을 편집했을 때 반응이 더 컸습니다.
  - L 편집은 89%, O 편집은 27%의 관측에서 후속 token을 바꿨습니다.
  - 다만 donor 거리가 L 쪽에서 평균적으로 커서 거리 교란이 일부 섞여 있습니다.
- **해석 범위:** 다른 기반 모델 계열(SigLIP/Gemma 2)에서 같은 방향의 위치 반응이 관찰됐습니다. 그러나 주 분석은 확증력이 약하고, 2개 task·명령 수준의 결과입니다. 운동, 성공률, 일반화는 주장하지 않습니다.
- **중요 발견:** transformers 4.47의 `generate`가 이전 호출의 HybridCache를 재사용합니다. 그래서 prompt 길이가 다른 호출이 섞이면 같은 입력에서도 공식 출력이 달라졌습니다(A3). 이후 공식 호출마다 cache를 새로 만들도록 고치고 feasibility와 pilot을 다시 실행했습니다.

## 재실행 명령
```bash
source /root/VLA/simpler/env.sh            # transformers 4.47 (spatialvla/site) + SimplerEnv; CUDA_VISIBLE_DEVICES=1 (RTX 5090)
cd /root/VLA/svla_wc_work
python scripts/wc_run.py --phase feasibility --phase-cap-min 30 --enable-gpu    # 빈 run/feasibility 필요
python scripts/wc_run.py --phase pilot --phase-cap-min 120 --enable-gpu
CUDA_VISIBLE_DEVICES="" python scripts/analyze.py run/pilot/records.jsonl analysis
CUDA_VISIBLE_DEVICES="" python scripts/verify_cpu.py run/pilot/records.jsonl analysis/summary.json
python scripts/plot_results.py analysis
```
CPU 재계산(`analyze.py`, `verify_cpu.py`)은 GPU와 simulator 없이 원시 token 기록만으로 결과를 복원합니다.
