### B: CPU 검증

압축을 해제한 v04 루트에서 실행한다.

```bash
python3 verify_20261023_v04.py
python3 verify_baseline_20261023_v04.py
```

필요한 Python 패키지는 NumPy와 Pillow다. 이전 v04 검토에서는 첫 검증기 25,957개 검사, 기존 VLA-0 검증기 668개 검사를 통과했다. 실행 결과가 이를 재현하는지 확인한다. 검증기가 실패하면 원인을 조사하고, 검사 조건을 지워 통과시키지 않는다. 새 GPU 추론 없이 검증한 범위와 저장된 로그에 의존한 범위를 구분한다.

입력의 `SHA256SUMS_20261023_v04.txt`를 확인하되, 원고나 빌드 산출물을 수정한 뒤에는 입력 해시와 달라진 파일을 변경 내역으로 기록한다. 실험 기록의 변화와 정상적인 원고·PDF 변경을 혼동하지 않는다.

### C: 원고에서 유지할 정의와 범위

- SpatialVLA 주 결과: **69관측 / 34 layouts / 2과제, Δ=0.048378 [0.025522, 0.072148]**. 두 과제별 결과는 v04 표와 JSON을 따른다. Δ는 정규화 행동 거리 차이이며 성공률 pp가 아니다.
- SpatialVLA 거리 D_S는 a3·a4의 여섯 운동 성분, 총 12개 성분의 평균 절대 차이다. VLA-0의 30개 정수 성분 거리와 구분한다.
- O와 L에는 같은 sampled chunk의 각 위치에 대응하는 행동이 들어간다. 하나의 동일한 벡터를 양쪽에 넣는 설계가 아니다. 각 위치 gripper는 자연값을 유지한다.
- O에서 a2는 자연값으로 고정된다. 따라서 이전 위치에서 중간 행동을 거쳐 일어나는 전체 전파 효과로 표현하지 않는다.
- 매칭 donor가 확보된 관측은 105개 중 69개이며, donor 거리 비율 허용 범위는 0.8–1.25다. 정확한 거리·방향 동일성이나 전체 관측으로의 일반화를 주장하지 않는다.
- 서랍 보조 결과: 35관측 / **15 reset scenarios / 7 recorded pose groups**. 기존 시나리오 가중 Δ=0.144881, 시나리오 bootstrap 구간 [0.090537, 0.209987]. 사후 자세군 bootstrap 구간 [0.075122, 0.235905]은 별도 민감도 분석이다. 동등한 자세군 가중은 다른 추정 대상이다. 두 과제 주 결과에 합치지 않는다.
- 서랍의 collection-time natural 출력 비교는 불가하다. R/adapter 토큰 검사는 통과했지만, R logit 차이 최대 0.5를 bitwise logit parity로 바꾸지 않는다.
- 별도 SpatialVLA cross-step 성공률 연구와 새 within-call 명령 수준 연구를 구분한다. 후속 명령 반응을 성공률 개선으로 확대하지 않는다. VLA-0의 4개 task–state units 운동 결과도 성공률 검증으로 표현하지 않는다.
- 모델 선택은 조사한 구현에 한정한다. FAST는 autoregressive이며 시간 비국소적 표현을 쓴다. SpatialVLA가 모든 공개 모델 중 유일하다고 쓰지 않는다. WorldVLA의 제3자 fork 출처와 revision을 유지한다.
- `pre-specified`를 외부 등록 근거 없이 `pre-registered`로 되돌리지 않는다. 역사적 원시 프로토콜은 수정하지 않는다.
- 새 방법이나 성능 향상, backbone의 인과 효과, AutoVLA의 위치 독립성·상위 군집 유의성을 새로 확립했다고 주장하지 않는다. 결론을 강화하려고 분석 단위·제외 규칙·효과 정의를 사후에 바꾸지 않는다.

### D: PDF와 LLM 사용 명세

```bash
python3 build_20261023_v04.py
```

- v04에는 공식 CVPR 2027 v1 author kit가 `format/`에 들어 있다. 현재 스타일 파일은 배포본과 같다. 여백·글꼴을 줄여 페이지를 맞추거나 2026 스타일로 되돌리지 않는다.
- `cvpr.sty` SHA-256: `1cd7f434b13d41c475df4a1901a5d82d9ca8b80b8cf6205dc4602a5c164286b4`.
- `.bst` SHA-256: `e38e6166bd7b1e6d23a1b79dcdb55c656e4fcdbe91bdf6b50d827e6b5d1aacfc`.
- 현재 기준은 본문 8쪽, 9쪽부터 LLM Usage Statement와 참고문헌, 본문 PDF 총 10쪽이다. 보충자료는 총 19쪽, 참고문헌은 19쪽부터다. 오류·미정의 참조·overfull이 없어야 하며, 전 페이지를 렌더링해 표·그림·글자 겹침과 잘림을 점검한다.
- `paper/llm_usage_statement_20261023_v04.tex`는 확인된 ChatGPT/Codex 사용 내역의 초안이다. 자신이 접근 가능한 실행 기록에서 추가 도구 이름과 사용 범위를 확인할 수 있으면 사실대로 반영한다. 알 수 없는 과거 사용 내역을 추측하거나 저자 확인 완료로 쓰지 않는다. 저자만 확인 가능한 부분은 최종 보고서에 남긴다.
- 원 서버에 pdfLaTeX/BibTeX가 없으면 기존 환경과 여유 공간을 확인하고, 기존 데이터·가중치를 보존하는 범위에서 빌드 환경을 준비한다. 설치가 불가능하면 확인된 원인을 기록하고 동봉된 검증 완료 PDF와 로그를 보존한다. 실제로 하지 않은 서버 재빌드를 성공으로 기록하거나 다른 엔진 결과를 pdfLaTeX 결과라고 쓰지 않는다.
- 사용 명세 등 TeX를 변경했다면 최종 PDF도 그 변경과 일치해야 한다. 빌드가 불가능한 환경에서는 source 수정과 마지막 검증 PDF 사이의 차이를 명시한다.

## 3. 진행 방식

통상적인 경로·환경·표기 문제는 직접 해결하고 계속 진행한다. A를 끝낸 뒤 B를 다시 요청하라는 식으로 사용자에게 작업을 분할하지 않는다. 한 검증에 문제가 있어도 독립적으로 진행 가능한 나머지 점검과 결과 정리는 끝낸다.

과학적 결론에 영향을 주는 원시 기록의 모순이나 실제로 얻을 수 없는 입력이 있으면 해당 부분을 BLOCKED로 표시한다. 다른 작업까지 조용히 중단하거나 실행하지 않은 내용을 완료로 채우지 않는다. 사용자의 추가 정보가 필요한 질문은 가능한 작업과 구체적인 결과물을 만든 뒤 최종 보고서에 모은다.

## 4. 한 번에 반환할 결과

실행일의 한국시간 날짜와 버전을 파일명에 넣는다. 예시는 `CVPR_V04_SERVER_APPLY_RESULT_20261023_v01.zip`이다.

결과 ZIP에 다음을 포함한다.

1. 실제 반영한 TeX·그림·스타일·검증 코드와 최종 본문/보충 PDF.
2. 두 CPU 검증기 결과 JSON과 실행 로그, 빌드·시각 QA 기록.
3. 버전이 있는 README: A–E의 PASS / FAIL / BLOCKED, 적용 경로, 명령·종료 코드, 변경 사항, 남은 저자 확인 사항.
4. v04 입력 대비 diff 또는 변경 파일 목록과 새 SHA-256 manifest.
5. 새 GPU 실험 수행 여부와, 서버에서 재실행한 검증·동봉 기록만 확인한 검증의 구분.

기존 원시 ZIP을 중복 동봉할 필요는 없지만, 생략한 입력 파일의 이름·해시와 재현에 필요한 위치를 명시한다. PDF만 반환하거나 중간 단계 결과만 전달하고 끝내지 않는다. **이번 한 요청에서 원고 반영부터 검증·최종 패키징까지 완료한 뒤 결과를 한 번에 반환하라.**
