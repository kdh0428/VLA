# reproducibility_followup5.zip — review_followup5 add-on (2026-10-18)

Lets a third party recompute every review_followup5 CPU result from the shipped inputs, including the analysis of the new
GPU run (B_NUMERIC raw records are shipped). Earlier rounds: `reproducibility_minimal.zip` (review_followup4).
`MANIFEST.csv` lists every file with byte size, sha256 and original path; `PINS.csv` pins model / data revisions;
`MISSING.md` lists what is not included.

## Precedence

`VLA/autovla_misalignment_poc/outputs/review_followup5/{STATUS.md, CLAIM_CHANGES.md, MANUSCRIPT_REVISION.md}` supersede
review_followup4 wording where they conflict. The protocol (`FOLLOWUP5_PROTOCOL.md`, hash in `PROTOCOL_LOCK.json`) is a
local file freeze, not a public preregistration; changes after results are in `AMENDMENTS.md`.

## Regenerate (CPU only)

    python -m zipfile -e reproducibility_followup5.zip <dir>
    PY=/path/to/python3.9 bash <dir>/regen.sh          # FAST=1 skips the coverage simulation (~2 min)

Requirements: Python 3.9, numpy 1.23.4, pandas 2.3.3, scipy 1.13.1, pyarrow 21.0.0.

| target | script (`scripts/review_followup5/`) | regenerates |
|---|---|---|
| A_STATS_coverage | `a_stats_coverage.py` | coverage study on the real AutoVLA cluster structures; interval selection |
| A_STATS_audit | `a_stats_audit.py` | old vs new AutoVLA intervals, margin verdicts, MME decisions |
| A_B2_CLUSTER | `a_b2_cluster.py` | B2 contrasts with drive / day-vehicle / component clusters, Holm, component map |
| B_NUMERIC_analysis | `b_numeric_analyze.py` | endpoint excess over every baseline under S0 / SE / SF, paired changes, materiality |
| C_power | `c_power.py` | component-level power / precision plan |

The comparison parses numeric lists stored as text (e.g. CI columns "[lo, hi]") and compares them numerically
(rtol 1e-9); timing / location fields are ignored. Not regenerated by the script: the GPU run itself (`b_numeric_runner.py`,
needs the AutoVLA checkpoint and images) and `c_disjoint.py` (needs network access and the on-disk navhard metadata).
