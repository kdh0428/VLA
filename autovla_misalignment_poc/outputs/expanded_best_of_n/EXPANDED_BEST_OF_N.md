# 표본 확대: 새 log 56개(4,563 장면)에서의 best-of-N 확인

**답: 확인됐습니다.** 이전 실험에 한 번도 쓰지 않은 navtest log 56개(장면 4,563개, 자연 실패 98개)에서, 미리 고정한 선택 규칙이 모집단 실패율과 궤적 오차를 모두 유의하게 줄였습니다. **순위 합**(엔트로피 순위 + log-likelihood 순위)은 A− 비율을 2.15 → 1.45%(−0.70%p [−1.07, −0.33], McNemar p = 4e-4, 상대 −33%), FDE5를 0.758 → 0.484 m(−36%)로, **최대 log-likelihood**는 A−를 1.47%(−0.68%p [−0.97, −0.39], p = 3e-6)로 줄였습니다. **최소 엔트로피**는 실패 장면을 가장 많이 구하지만(59%) 정상 장면에서 새 실패를 만들어 순효과가 유의하지 않았습니다(−0.26%p [−0.71, +0.19]).

- 스크립트: `tools/stream_expanded_best_of_n.sh` (shard 스트리밍), `scripts/expanded_best_of_n.py` (GPU), `scripts/analyze_expanded_best_of_n.py`
- 데이터: OpenScene navtest 카메라 shard 6–17의 navtest log 56개. PoC의 28개 log(shard 0–5)와 겹치지 않음. shard를 하나씩 받아 전처리·디코딩한 뒤 이미지를 지우는 방식으로 디스크 15 GB 안에서 처리.
- 실행: 2026-09-29, shard 6–13은 RTX 5090(3,294 장면, 39 log), 14–17은 RTX 3080 Ti(`VLA_LOW_MEM=1`, 1,269 장면, 17 log). 후보 = 자연 계획(T 0.01) 1개 + T 1.0 16개, seed 0. 장면당 2–4 s, 오류 0, CoT stub 0.
- 선택 규칙은 실험 18–19에서 정의·고정한 그대로(`analyze_best_of_n.pick`)입니다. 이 데이터를 보고 바꾼 것은 없습니다.

## 1. 왜 필요했나

실험 19에서 확신도 기반 선택은 모집단 FDE를 확실히 줄였지만, 실패율 감소(−0.4%p)는 자연 실패 장면 52개로는 CI가 0을 겨우 포함했습니다. 또 순위 합 규칙은 실험 19의 결과를 본 뒤에 정한 규칙이었습니다. 새 log에서 규칙을 고정한 채 표본을 늘려 판정합니다.

## 2. 설계

각 새 장면에 대해 자연 계획의 stub을 생성하고(`<think>\nThis is a` + 첫 action 전까지 자유 디코딩, 다른 실험과 동일), 한 batch에서 후보 17개를 디코딩합니다. **모든 장면에 선택 규칙을 적용하므로 모집단 효과를 가중치 없이 직접** 잽니다. 실패 = P/R/A 5 s A−, 강한 실패 = A− ∧ FDE5 > 3 m. CI는 log 단위 cluster bootstrap(56 log), 이진 지표는 McNemar.

## 4. 해석

1. **선택 방식은 새 데이터에서 재현됩니다.** 규칙을 바꾸지 않고 log 56개에 적용했을 때, 순위 합과 최대 log-likelihood가 실패율을 약 1/3, 궤적 오차를 26–36% 줄였습니다. 5,000개 가까운 장면과 98개 자연 실패로 실험 19의 검정력 문제가 해결됐습니다.
2. **최대 log-likelihood는 가장 안전하고, 순위 합은 가장 효과적입니다.** max_loglik은 새 실패를 거의 만들지 않고(7 vs 구제 38), ranksum은 더 많이 구하고(55) 더 많이 만들지만(23) 순효과와 FDE 개선이 가장 큽니다.
3. **최소 엔트로피만으로는 부족합니다.** 실패 장면 구제율은 가장 높지만(59%) 정상 장면에서 새 실패를 46개 만들어 상쇄됩니다. 실험 19 곡선에서 보인 "설정에 민감함"은 이것 때문이며, log-likelihood 순위와 합치면(ranksum) 그 부작용이 줄어듭니다.
4. **상한은 아직 멉니다.** 17개 후보 중 최선을 고르면(oracle) 실패율이 0.24%까지 내려갑니다. 선택 신호를 더 정확하게 만들면 이득이 커질 여지가 큽니다.

## 5. 한계

- 모든 결과는 open-loop 5 s 평가입니다. 진짜 closed-loop(NAVSIM v2 pseudo-simulation 등) 검증은 하지 않았습니다.
- 자연 계획(비교 기준)도 이 실험에서 새로 생성했습니다(저장된 full_extract 기록이 없는 장면). 자연 실패율은 5090에서 2.40%, 3080 Ti에서 1.50%로, 서로 다른 log이기도 하지만 GPU 수치 차이도 섞여 있습니다. 모든 비교는 같은 실행 안의 쌍대 비교입니다.
- seed 0 한 번의 실행입니다. 규칙과 설정은 실험 18–19에서 고정했습니다.
- 후보 17개를 디코딩하는 비용(action 디코딩 약 17배, prefix 공유)은 줄이지 않았습니다. 앞쪽 step만으로 고르는 조기 가지치기는 실험 19에서 효과가 없었습니다.
