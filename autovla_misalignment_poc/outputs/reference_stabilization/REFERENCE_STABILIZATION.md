# GT 없이 feedback을 안정화할 수 있는가 — 비-oracle motion 참조

**답: 부분적으로 가능합니다. 모델의 이전 frame 계획을 참조로 쓰면 A− 증폭이 47.1% → 33.2%로 줄고(GT 효과의 약 1/3), 정상 장면(A+)은 해치지 않습니다. 단순 운동학 외삽(CTRA)은 오히려 해롭습니다. 효과의 크기와 방향은 참조의 motion이 GT에 얼마나 가까운지로 결정됩니다.**

- 스크립트: `scripts/reference_stabilization.py` (GPU 1), `scripts/analyze_reference_stabilization.py`, 공용 `scripts/_planner.py`, frame 준비 `scripts/build_frame_scenes.py`
- 데이터: equal-distance 집합(A− 52 장면 / 365 단위, A+ 156 장면 / 1043 단위, 이전 frame이 없는 A+ 6 단위는 prev 조건에서 제외)
- 실행: 2026-09-29, RTX 5090, torch 2.8.0+cu128, T = 0.01, seed 0, 11분

## 1. 질문

실험 9–11: 첫 불일치 이후 2–4 step 동안 조건화 context를 GT로 바꾸면 발산의 90–95%가 사라지고(실험 9–10), GT 토큰 자체가 아니라 **GT와 motion이 같은 토큰**이면 충분합니다(실험 11). 실제 주행에는 GT가 없으므로, 추론 시점에 얻을 수 있는 참조의 motion으로 같은 교정을 했을 때 얼마나 남는지를 봅니다.

## 2. 설계

harness와 교정 창 정의는 temporal_feedback_window와 동일합니다: context 위치 t*+o (1 ≤ o < 1+w)를 참조 토큰으로, 그 외는 모델 자신의 토큰으로 두고, 실행 action은 항상 모델 샘플입니다. 교정 시점(t*)은 이번에도 oracle이며, **교정 내용만** 비-oracle입니다.

| 참조 | 만드는 법 | 미래 정보 |
|---|---|---|
| `gt` | GT 토큰 | 있음 (oracle 기준) |
| `kin` | 현재 ego 상태의 CTRA 외삽(속도, 종가속도, 마지막 history 구간의 yaw rate)을 GT 토큰과 **같은 routine으로** codebook 토큰화 | 없음 |
| `prev` | 0.5 s 전 frame에서 모델이 새 prompt로 세운 계획(natural 경로)을 한 step 민 것: 토큰은 step별 국소 motion이므로 prev[j] = 이전 계획[j+1] | 없음 |

창: w2, w4, all(t* 이후 전체). 토큰화 검증: 3개 장면에서 `tokenize(GT 궤적)`이 저장된 GT 토큰과 완전히 일치.

### GT 없는 gate로 좋은 참조만 골라 쓸 수 있는가

추론 시점에 관측 가능한 세 신호로 "참조를 쓸지"를 정하고(임계값은 leave-one-log-out으로 선택, 목표 = 평균 FDE 최소), 기존 행의 결과로 정책을 평가했습니다.

| gate 신호 | 참조 오차와 Spearman | A− 증폭 / FDE | A+ 증폭 / FDE |
|---|---:|---|---|
| (항상 prev_w4) | – | 33.2% / 5.34 | 3.2% / 2.02 |
| prev ↔ kin 불일치 | 0.39 | 35.6% / 5.55 | 3.4% / 2.05 |
| 모델 자기 출력 ↔ prev 거리 | 0.57 | 32.9% / 5.34 | 3.2% / 2.02 |
| 불일치 토큰 ↔ prev 거리 | 0.51 | 35.6% / 5.50 | 3.9% / 1.99 |

gate 신호는 참조 오차와 상관이 있지만 **항상 적용보다 낫지 않습니다**. 교차검증이 고른 임계값은 사실상 "항상 적용"이었습니다. 참조가 나쁜 단위는 모델 자신도 이미 크게 벗어나 있는 단위라, 거기서 참조를 써도 잃는 것이 적기 때문입니다.

## 4. 해석

1. **이전 계획은 gate 없이 켜 둘 수 있는 안전한 부분 mitigation입니다.** A−에서 GT 효과의 약 30–34%를 얻고, A+에서는 해가 없습니다(수치상 약간 개선).
2. **단순 운동학 prior는 해롭습니다.** CTRA는 감속·회전을 5 s 동안 연장해 motion이 GT에서 멀어지고(FDE 7–8 m), 그 motion이 조건화되면 정상 장면의 증폭이 4% → 9–16%로 늘어납니다. "직전 motion을 교정하면 좋다"가 아니라 "**GT에 가까운 motion으로** 교정해야 좋다"입니다.
3. **상한은 참조 품질이 정합니다.** prev의 효과가 1/3에 그치는 이유는 이전 계획 토큰이 GT와 17–24%만 일치하기 때문이며, 참조가 가까운 경우에는 GT 교정의 대부분이 재현됩니다. 더 좋은 비-oracle 참조가 곧 더 좋은 mitigation입니다.

## 5. 한계

- **교정 시점은 oracle**(t*)입니다. 교정 내용만 비-oracle이며, 완전한 배치 조건은 receding-horizon 실험에서 봅니다.
- `_planner.Planner`는 stub을 새로 생성하므로 저장된 natural 계획과 토큰이 항상 같지는 않습니다(검사한 4장면 중 1개 동일, ADE 수준은 동일). 이전 계획은 이 경로로 만들었습니다.
- A− 52 장면, 단일 seed, T = 0.01. prev의 A− 효과는 log cluster CI 상한이 0에 가깝습니다.
- CTRA는 하나의 단순 prior일 뿐이며, 지도·경로를 쓰는 planner 참조는 다루지 않았습니다.
